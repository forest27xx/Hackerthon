# 快乐下单事务所项目路线图

## Demo 一句话

一个模拟吃喝玩乐下单的小程序游戏。它把普通“点奶茶/点外卖”的过程改造成一次心理奖励体验：用户选择今日下单目的，点商品、凑 combo、处理配送事件，最后生成一张快乐订单小票和美食人格 MBTI。

## 第一版已完成

- React/Vite 前端 demo。
- 今日下单目的选择。
- 菜单分类、商品卡、规格弹窗、购物车。
- 快乐值、健康值、饱腹值、清醒值、安全值。
- combo 触发。
- 配送事件小游戏。
- 速度、安全、健康、完整度、信任值。
- 16 类美食人格 MBTI。
- 结果卡保存和分享文案复制。

## 下一阶段目标

### 1. 视觉体验升级

负责人建议：前端 UI 同学。

重点：
- 首页目的选择卡片更精致。
- 下单页继续参考奶茶/外卖小程序。
- 商品卡要更“有食欲”和更容易扫读。
- 配送事件页要更像小游戏，不只是问答卡片。
- 结果卡要适合截图传播。

验收：
- 手机 viewport 下文字不溢出、不遮挡。
- 主要按钮一眼能懂。
- 至少能拿出 2 张可用于展示 PPT 的截图。

### 2. 内容和素材扩量

负责人建议：内容策划同学。

第一批目标：
- 商品 60+。
- combo 20+。
- 配送事件 40+。
- 结果人格文案 16 类，每类至少 3 个变体。
- 商品图片覆盖率 80%+。

内容原则：
- 名字要好笑、好记、像真实小程序又有一点荒诞。
- 健康和食品安全提示要轻，不要像科普考试。
- 不做真实医疗建议。

### 3. 配送事件玩法增强

负责人建议：事件/规则同学。

方向：
- 事件不只是加减分，要有“取舍感”。
- 让用户在速度、完整度、安全、健康、信任之间做选择。
- 增加连续事件影响，比如前面选择“冷热分袋”，后面撒漏风险降低。
- 增加隐藏成就，比如“守护骑手”“包装达人”“低糖谈判家”。

### 4. 美食人格与 AI 化

负责人建议：AI/算法同学。

当前是本地规则。后续可以：
- 把 16 类人格文案做得更像社交测试结果。
- 把用户整个订单过程转成 prompt，由 AI 生成更个性化文案。
- 保留本地规则作为 fallback，避免 demo 现场网络或模型失败。
- 增加“今日订单名生成器”。

### 5. 部署和演示

负责人建议：集成部署同学。

重点：
- 选择部署平台：Netlify / Vercel / Cloudflare Pages / 飞书妙搭。
- 固定一个公网演示链接。
- 准备演示路径：推荐目的 -> 加商品 -> 下单 -> 选择事件 -> 结果卡。
- 准备 1 分钟和 3 分钟两个版本的讲稿。

## 四人协作建议

| 角色 | 分支 | 主要目录 | 交付物 |
|---|---|---|---|
| A 内容策划 | `feature/frontend` 或独立内容分支 | `modules/frontend/src/data/catalog.ts`、`modules/frontend/src/assets/menu` | 商品、combo、图片命名、结果文案 |
| B 前端 UI | `feature/frontend` | `modules/frontend/src/App.tsx`、`modules/frontend/src/styles.css` | 页面、交互、移动端适配 |
| C 规则事件 | `feature/ai-core` 或 `feature/frontend` | `modules/frontend/src/lib/gameEngine.ts`、事件数据 | 事件机制、分数系统、人格规则 |
| D 集成部署 | `feature/integration-deploy` | `modules/integration-deploy`、根文档 | 部署、演示链接、演示材料 |

如果多人都要改 `catalog.ts`，建议先拆任务表，避免同时改同一段数组导致冲突。

## 推荐迭代顺序

1. 先把 demo 部署出去，所有人能访问同一个版本。
2. 内容同学补商品和图片。
3. 前端同学优化下单页和结果卡。
4. 事件同学增强配送小游戏。
5. AI/算法同学增强人格文案。
6. 集成同学做最终演示路径、截图、PPT。
